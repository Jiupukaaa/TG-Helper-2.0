# TG Helper 2.0

Личный Telegram-ассистент без ИИ. Бот помогает хранить заметки, создавать напоминания, вести график работы и сохранять ссылки, фотографии и GIF.

Проект работает на **Cloudflare Workers**. Данные хранятся в **Cloudflare D1**.

## Возможности

### 📝 Заметки

- создание текстовых и голосовых заметок;
- просмотр списка заметок с постраничной навигацией;
- открытие заметки по номеру;
- просмотр длинных заметок по страницам;
- редактирование и замена голосовых заметок;
- удаление одной или нескольких заметок;
- повторная отправка сохранённого голосового сообщения.

Заметки длиной **300 символов и более** выводятся отдельной страницей. Длинные заметки дополнительно разбиваются на страницы с учётом ограничений Telegram.

### ⏰ Напоминания

- создание текстовых и голосовых напоминаний;
- просмотр и удаление напоминаний;
- повторение ежедневно, еженедельно или ежемесячно;
- от 2 до 52 повторений;
- автоматическая отправка наступивших напоминаний;
- обработка ошибок отправки и повторные попытки.

Дата и время вводятся в формате `DD.MM.YYYY HH:mm`. В базе время хранится в UTC, а пользователю показывается с учётом его часового пояса.

### 📅 График работы

- создание смен на отдельных датах;
- циклические графики 2/2, 3/3, 5/2 и собственные циклы;
- просмотр, изменение и удаление смен;
- календарь смен по месяцам;
- напоминания, связанные со сменами.

### 🔖 Сохраненки

- сохранение ссылок, фотографий и GIF;
- просмотр и фильтрация по типу;
- повторная отправка фотографий и GIF;
- удаление одной или нескольких сохраненок.

### 🔐 Ограничение доступа

Доступ к боту разрешён только Telegram ID, указанным в Worker variable `ALLOWED_TELEGRAM_IDS`. Можно указать несколько ID через запятую. Если список пуст, доступ запрещён всем пользователям.

## Технологии и архитектура

- **Cloudflare Workers** — выполнение Telegram-бота и обработка запросов;
- **Cloudflare D1** — база данных SQLite;
- **TypeScript**;
- **grammY** — Telegram Bot API;
- **Luxon** — работа с датой и временем;
- **GitHub** — исходный код и автоматический деплой.

Один Worker обрабатывает webhook и запускает плановые задачи. Отдельный Cron Worker не требуется.

```text
Telegram
   │
   │ HTTPS webhook
   ▼
Cloudflare Worker: tg-helper-2-0
   ├── POST /telegram
   ├── GET  /health
   ├── GET  /
   └── scheduled() — каждые 5 минут
             │
             ▼
        Cloudflare D1
```

## Развёртывание на Cloudflare

### 1. Что потребуется

- аккаунт [Cloudflare](https://dash.cloudflare.com/);
- GitHub-репозиторий проекта;
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).

### 2. Подключение GitHub-репозитория

1. Откройте Cloudflare Dashboard → **Workers & Pages**.
2. Создайте Worker через подключение GitHub-репозитория или откройте существующий Worker.
3. Выберите репозиторий `Jiupukaaa/TG-Helper-2.0` и ветку `main`.
4. Для проекта используется конфигурация из корневого файла `wrangler.jsonc`.
5. Убедитесь, что корневая директория проекта — корень репозитория, а команда деплоя — `npm run deploy`.

Имя Worker, точка входа, привязка D1 и расписание Cron уже заданы в `wrangler.jsonc`. При подключённом автодеплое новые коммиты в выбранной ветке запускают сборку и деплой.

### 3. База данных D1

Проект использует D1:

| Параметр | Значение |
|---|---|
| Имя Worker | `tg-helper-2-0` |
| Имя D1 database | `tg-helper` |
| Binding | `DB` |
| Каталог миграций | `cloudflare/migrations` |

Идентификатор базы данных уже указан в `wrangler.jsonc`. Не заменяйте его при настройке существующего проекта: это приведёт к подключению другого экземпляра D1.

Миграции схемы хранятся в `cloudflare/migrations/`. Для применения новых миграций к удалённой базе используется GitHub Actions workflow **Apply D1 migrations**:

1. Откройте GitHub → **Actions**.
2. Выберите **Apply D1 migrations**.
3. Нажмите **Run workflow**.

Для этого workflow в GitHub Repository Secrets должны быть заданы:

- `CLOUDFLARE_API_TOKEN` — API Token с необходимыми правами на Workers и D1;
- `CLOUDFLARE_ACCOUNT_ID` — идентификатор аккаунта Cloudflare.

Не запускайте миграции повторно без необходимости и не удаляйте существующую D1 database.

### 4. Переменные и секреты Worker

Откройте Cloudflare → **Workers & Pages** → `tg-helper-2-0` → **Settings → Variables and Secrets**.

Добавьте следующие параметры:

| Имя | Тип | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Secret | Токен Telegram-бота от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | Secret | Секрет проверки Telegram webhook |
| `CRON_SECRET` | Secret | Секрет для защищённого ручного запуска отправки напоминаний |
| `ALLOWED_TELEGRAM_IDS` | Text | Разрешённые Telegram ID через запятую |

`ALLOWED_TELEGRAM_IDS` — именно **Worker variable**, а не Build variable. Переменные в разделе **Builds** используются процессом сборки и не передаются автоматически работающему Worker.

В `wrangler.jsonc` включён параметр `keep_vars: true`, чтобы переменные, заданные через Cloudflare Dashboard, сохранялись при деплое через Wrangler.

Не добавляйте токены и другие секреты в GitHub, исходный код или README.

### 5. Настройка Telegram webhook

Webhook должен указывать на адрес Worker с путём `/telegram`:

```text
https://<имя-воркера>.<поддомен>.workers.dev/telegram
```

Установите webhook через Telegram Bot API, передав тот же секрет, который сохранён в Worker как `TELEGRAM_WEBHOOK_SECRET`:

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<имя-воркера>.<поддомен>.workers.dev/telegram",
    "secret_token": "<TELEGRAM_WEBHOOK_SECRET>"
  }'
```

Telegram передаёт секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`. Worker проверяет его перед обработкой обновления.

Проверить текущий webhook можно запросом:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo
```

### 6. Автоматическая отправка напоминаний

В `wrangler.jsonc` настроен Cron Trigger:

```text
*/5 * * * *
```

Cloudflare вызывает метод `scheduled()` того же Worker каждые пять минут. Он находит наступившие напоминания, отправляет их через Telegram Bot API и обновляет их состояние в D1.

Отдельно настраивать GitHub Actions для регулярной отправки напоминаний не нужно.

### 7. Проверка работы

После деплоя проверьте:

- главная проверка Worker: `https://<worker-host>/` — ответ `ok`;
- health endpoint: `https://<worker-host>/health` — JSON `{"ok":true}`;
- Telegram webhook указывает на `/telegram`;
- бот отвечает на команду `/start`;
- разрешённый Telegram ID указан в `ALLOWED_TELEGRAM_IDS`;
- часовой пояс установлен командой `/settimezone`;
- тестовое напоминание успешно отправляется.

## Команды Telegram-бота

### Основные

- `/start` — главное меню;
- `/notes` — заметки;
- `/note <номер>` — открыть заметку;
- `/reminders` — напоминания;
- `/cancelreminder <номер>` — удалить напоминание;
- `/shifts` — график работы;
- `/saved` — сохранённые ссылки, фото и GIF;
- `/today` — сводка на сегодня;
- `/settimezone <зона>` — установить часовой пояс.

Пример установки часового пояса:

```text
/settimezone Europe/Amsterdam
```

Поддерживаются стандартные IANA-названия, например `Europe/Amsterdam`, `Europe/Moscow`, `Asia/Yerevan`, `America/New_York`.

Если часовой пояс не установлен, создание напоминаний и смен блокируется до его настройки.

## Безопасность

1. `ALLOWED_TELEGRAM_IDS` ограничивает доступ к боту.
2. `TELEGRAM_WEBHOOK_SECRET` проверяет подлинность входящих webhook-запросов.
3. `CRON_SECRET` защищает endpoint ручного запуска отправки напоминаний.
4. Пользователь работает только со своими заметками, напоминаниями, сменами и сохраненками.
5. Секреты хранятся в Cloudflare Worker Secrets и не должны попадать в репозиторий.

## Ограничения и особенности

- Проект не использует ИИ или LLM.
- Telegram webhook должен быть доступен по публичному HTTPS-адресу.
- Плановая отправка напоминаний зависит от Cron Trigger Cloudflare.
- Между отправкой сообщения Telegram и записью статуса в D1 нет общей транзакции. При редком сбое между этими операциями одно напоминание теоретически может быть отправлено повторно.
